```bash
goro inspect -s web.search
```

## Options

| Option | Meaning |
| --- | --- |
| `-s`, `--slug` | The tool slug, for example `web.search`. Required. |

Plus the [global options](/cli/overview#global-options).

## The input table is the real schema

Goro forwards your input to the underlying tool unchanged and hands back its
rows untouched. The fields listed are the fields the tool itself accepts, not a
translation, so anything the tool takes works even if it is not in the table.

<Note>
  Fields that cost extra are called out in the tool's notes. Turning on a paid
  extra raises what the call actually consumes, and therefore what you are
  charged, but never above the ceiling.
</Note>

## The price block

The `price` block spells out three things:

- the ceiling for a single call, always written as "up to",
- that billing follows actual usage, at the stated multiple of provider cost,
  with a floor,
- that the hold is sized from your specific request, not from the ceiling.

An unknown slug exits `1`:

```
$ goro inspect -s nope.nope
Error unknown endpoint: nope.nope
```

## Copy the run line
